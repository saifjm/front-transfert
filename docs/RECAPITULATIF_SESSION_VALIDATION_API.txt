  ✅ 13 CONTRÔLES DE VALIDATION IMPLÉMENTÉS
  ─────────────────────────────────────────
  
  La fonction handleSubmit() effectue les validations suivantes :
  
  1️⃣  Champs obligatoires de base
      • Type Dossier AVA, RNE, Compte, Activité, Déclaration Fiscale
  
  2️⃣  Sous-activité conditionnelle
      • Obligatoire UNIQUEMENT pour types dossier 3 et 5
  
  3️⃣  Validation RNE avec algorithme BCT
      • Format : 7 chiffres + 1 lettre clé
      • Utilise controleRne() - traduction fidèle PL/SQL
  
  4️⃣  Validation téléphone tunisien (multi-valeurs)
      • Formats : 8 chiffres, +216XXXXXXXX, 00216XXXXXXXX
      • Supporte plusieurs numéros séparés par ";"
  
  5️⃣  Validation email (multi-valeurs)
      • Format standard email
      • Supporte plusieurs emails séparés par ";"
  
  6️⃣  Cohérence autorisation BCT
      • Numéro ET Date ensemble ou aucun
  
  7️⃣  Montant importation (conditionnel)
      • Type=3 ET Activité=24 → >= 200 000 TND
      • Autres cas → doit être vide
  
  8️⃣  Montant avance (conditionnel)
      • Banque sélectionnée ET Type≠3 → = 0
      • Banque sélectionnée ET Type=3 → >= 0
  
  9️⃣  Documents obligatoires
      • Au moins 1 document requis
  
  🔟  Bénéficiaires obligatoires
      • Au moins 1 bénéficiaire requis
  
  1️⃣1️⃣  Bénéficiaires complets
      • Tous les champs obligatoires pour chaque bénéficiaire
  
  1️⃣2️⃣  Date pièce bénéficiaire
      • Date <= date du jour
  
  1️⃣3️⃣  Banque provenance (si sélectionnée)
      • Tous les montants obligatoires
      • Formule solde respectée

└──────────────────────────────────────────────────────────────────────────────┘

  1️⃣ TRADUCTION FIDÈLE PL/SQL → JAVASCRIPT
  ─────────────────────────────────────────
  
  La fonction controleRne() est une traduction LIGNE PAR LIGNE du PL/SQL.
  Cela garantit une compatibilité 100% avec l'algorithme BCT officiel.
  
  Exemple de conversion d'indexation :
  
  PL/SQL (1-based) :
    somme := Mod(somme, 23) + 1;
    cleMF := substr(vecteur, somme, 1);
  
  JavaScript (0-based) :
    somme = (somme % 23) + 1;
    cleMF = vecteur.substring(somme - 1, somme);
  
  2️⃣ VALIDATION EN CASCADE
  ────────────────────────
  
  Les validations s'arrêtent à la première erreur rencontrée.
  Cela évite de surcharger l'utilisateur avec trop de messages.
  
  3️⃣ WORKFLOW API SÉQUENTIEL
  ──────────────────────────
  
  ÉTAPE 1 DOIT réussir avant de lancer ÉTAPE 2.
  Si ÉTAPE 1 échoue → ARRÊT immédiat, pas d'appel ÉTAPE 2.
  
  4️⃣ GESTION D'ERREUR ROBUSTE
  ───────────────────────────
  
  • Try/catch global autour du workflow
  • Try/catch pour le parsing des erreurs API
  • Gestion des exceptions réseau
  • Finally pour toujours réactiver le bouton
  
  5️⃣ CONSERVATION DES DONNÉES
  ──────────────────────────
  
  En cas d'erreur API, le formulaire EST CONSERVÉ.
  L'utilisateur ne perd pas son travail et peut corriger puis réessayer.
  
  6️⃣ LOGS DÉTAILLÉS
  ─────────────────
  
  Chaque étape génère des logs console pour faciliter le débogage :
  • Données envoyées (DTO complet)
  • Réponses reçues (avec tous les champs)
  • Erreurs avec contexte
  • Récapitulatif final en cas de succès
