  de dossier AVA avant de soumettre les données via le workflow API en 2 étapes.

┌──────────────────────────────────────────────────────────────────────────────┐
│ ✅ VALIDATIONS CÔTÉ CLIENT (13 CONTRÔLES)                                    │
└──────────────────────────────────────────────────────────────────────────────┘

  Le bouton "Soumettre le dossier" déclenche la fonction handleSubmit() qui
  effectue les validations suivantes AVANT tout appel API :

  1️⃣ CHAMPS OBLIGATOIRES DE BASE
  ──────────────────────────────
  
  ✓ Type Dossier AVA         (codeTypeDosAva)
  ✓ Numéro Pièce Client      (noPieceClient) - RNE
  ✓ Compte Client            (compteClient)
  ✓ Code Activité            (codeActivite)
  ✓ Déclaration Fiscale      (declarationFiscale)
  
  ❌ Si manquant → Toast d'erreur avec liste des champs
  
  2️⃣ SOUS-ACTIVITÉ CONDITIONNELLE
  ────────────────────────────────
  
  ✓ Obligatoire UNIQUEMENT pour types dossier 3 et 5
  ✓ Vide pour types dossier 1, 2, 4
  
  ❌ Si type 3 ou 5 et manquant → Toast d'erreur
  
  3️⃣ VALIDATION RNE (MATRICULE FISCAL)
  ─────────────────────────────────────
  
  ✓ Format : 7 chiffres + 1 lettre clé (ex: 1695881M)
  ✓ 7 premiers chiffres < 9999999
  ✓ Clé de contrôle calculée selon algorithme BCT
  ✓ Utilise controleRne() - traduction fidèle PL/SQL
  
  ❌ Si invalide → Toast avec message détaillé
     "Clé de contrôle incorrecte. Attendu: M, trouvé: N"
  
  4️⃣ VALIDATION TÉLÉPHONE (MULTI-VALEURS)
  ────────────────────────────────────────
  
  ✓ Format : 8 chiffres | +216XXXXXXXX | 00216XXXXXXXX
  ✓ Supporte plusieurs numéros séparés par ";"
  ✓ Exemple valide : "12345678;+21687654321;0021611223344"
  ✓ Chaque numéro validé individuellement
  
  ❌ Si invalide → Toast avec numéro problématique
     "Numéro 2 invalide (\"123\"). Format attendu : 8 chiffres..."
  
  5️⃣ VALIDATION EMAIL (MULTI-VALEURS)
  ────────────────────────────────────
  
  ✓ Format standard email : xxx@xxx.xxx
  ✓ Supporte plusieurs emails séparés par ";"
  ✓ Exemple valide : "contact@test.com;admin@test.com"
  ✓ Chaque email validé individuellement
  
  ❌ Si invalide → Toast avec email problématique
     "Email 1 invalide (\"test.com\")"
  
  6️⃣ COHÉRENCE AUTORISATION BCT
  ──────────────────────────────
  
  ✓ Numéro BCT ET Date BCT → ensemble ou aucun
  ✓ Si numéro présent → date OBLIGATOIRE
  ✓ Si date présente → numéro OBLIGATOIRE
  
  ❌ Si incohérent → Toast d'erreur
     "DATE_BCT_OBLIGATOIRE: La date BCT doit être renseignée"
  
  7️⃣ MONTANT IMPORTATION (CONDITIONNEL)
  ──────────────────────────────────────
  
  📌 SI Type Dossier = 3 ET Code Activité = 24 :
     ✓ Montant OBLIGATOIRE
     ✓ Montant >= 200 000 TND
  
  📌 SINON :
     ✓ Montant doit être VIDE (0)
  
  ❌ Si règle non respectée → Toast d'erreur
     "Le montant d'importation doit être >= 200000"
  
  8️⃣ MONTANT AVANCE (CONDITIONNEL)
  ─────────────────────────────────
  
  📌 SI Banque de Provenance sélectionnée :
  
     • Type Dossier ≠ 3 → Montant Avance = 0 (obligatoire)
     • Type Dossier = 3 → Montant Avance >= 0 (libre)
  
  ❌ Si règle non respectée → Toast d'erreur
     "Le montant avance doit être 0 pour les types différents de 3"
  
  9️⃣ DOCUMENTS OBLIGATOIRES
  ─────────────────────────
  
  ✓ Au moins 1 document (pièce jointe) requis
  
  ❌ Si aucun document → Toast d'erreur
     "Au moins une pièce jointe est requise"
  
  🔟 BÉNÉFICIAIRES OBLIGATOIRES
  ─────────────────────────────
  
  ✓ Au moins 1 bénéficiaire requis
  
  ❌ Si aucun bénéficiaire → Toast d'erreur
     "Au moins un bénéficiaire doit être ajouté"
  
  1️⃣1️⃣ BÉNÉFICIAIRES COMPLETS
  ─────────────────────────────
  
  Pour CHAQUE bénéficiaire, tous les champs obligatoires :
  
  ✓ Type de Pièce        (typePieceBenef)
  ✓ Numéro de Pièce      (noPieceBenef)
  ✓ Nom                  (nomBenef)
  ✓ Adresse              (adresseBenef)
  ✓ Qualité              (qualite)
  ✓ Date Pièce           (datePiece)
  
  ❌ Si incomplet → Toast avec numéro et champs manquants
     "Bénéficiaire 2 incomplet - Champs manquants : Nom, Adresse"
  
  1️⃣2️⃣ DATE PIÈCE BÉNÉFICIAIRE
  ──────────────────────────────
  
  ✓ Date <= Date du jour (pas de date future)
  
  ❌ Si date future → Toast d'erreur
     "Bénéficiaire 1 - La date ne peut pas être dans le futur"
  
  1️⃣3️⃣ BANQUE PROVENANCE (SI SÉLECTIONNÉE)
  ─────────────────────────────────────────
  
  Si une banque est sélectionnée, TOUS les montants obligatoires :
  
  ✓ Montant Avance       (mntAvance)
  ✓ Montant Utilisé      (mntUtilise)
  ✓ Montant Autorisé     (mntAutorise)
  ✓ Montant Autorisé BCT (mntAutoriseBct)
  ✓ Solde                (solde)
  
  • Tous les montants doivent être >= 0
  • La formule du solde doit être respectée :
    
    SOLDE = Montant Autorisé + Montant Avance - Montant Utilisé + Montant Autorisé BCT
  
  ❌ Si montants manquants → Toast d'erreur
     "Tous les montants doivent être renseignés"
  
  ❌ Si montants négatifs → Toast d'erreur avec liste
     "Montant Utilisé, Solde ne peuvent pas être négatifs"
  
  ❌ Si formule incorrecte → Toast avec calcul
     "Le solde doit être égal à : 15000 + 10000 - 2000 + 5000 = 28000"
