┌──────────────────────────────────────────────────────────────────────────────┐
│ ✅ RÉALISATIONS                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

  1️⃣ IMPLÉMENTATION DU WORKFLOW EN 2 ÉTAPES
  ──────────────────────────────────────────
  
  ✅ ÉTAPE 1 : Initialisation du mouvement
     • Endpoint : POST /api/operations-deleguees-mvt/initialisation
     • Body : InitiationOuvertureDTO complet
     • Retour : OperationCreationResponseDTO (refOperation, numDossier)
     • Gestion des erreurs 400 et 500
  
  ✅ ÉTAPE 2 : Validation et création du dossier final
     • Endpoint : POST /api/operations-deleguees/validation/{numDossier}
     • Paramètre : numDossier reçu de l'ÉTAPE 1
     • Retour : OuvertureDossierDTO complet
     • Gestion des erreurs 404 et 422
  
  2️⃣ AJOUT DES TYPES TYPESCRIPT
  ──────────────────────────────
  
  ✅ OperationCreationResponseDTO
     • refOperation: number
     • numDossier: number
  
  ✅ OuvertureDossierDTO (complet avec tous les champs)
     • Informations du dossier principal
     • beneficiaires: BeneficiaireDTO[]
     • documents: DocumentDTO[]
     • avaMarche: AvaMarcheDTO
  
  ✅ BeneficiaireDTO (enrichi par rapport à BeneficiaireMvtDTO)
     • Ajout de numDossier, dateDossier, codeTypeDos, codeAgenceAva
  
  ✅ AvaMarcheDTO (identique à AvaMarcheMvtDTO mais sans id temporaire)
  
  3️⃣ GESTION DES ERREURS ROBUSTE
  ───────────────────────────────
  
  ✅ Parsing intelligent des erreurs API
     • Extraction de message/error du JSON
     • Fallback sur code HTTP + statusText si pas de JSON
  
  ✅ Messages d'erreur contextuels
     • 400 → "Requête invalide ou contrôle métier échoué"
     • 404 → "Numéro de dossier introuvable"
     • 422 → "Contrôles métier non satisfaits"
     • 500 → "Erreur serveur lors de l'initialisation"
  
  ✅ Arrêt du processus en cas d'erreur
     • Si ÉTAPE 1 échoue → Pas d'appel ÉTAPE 2
     • Si ÉTAPE 2 échoue → Formulaire conservé
  
  ✅ Gestion des exceptions réseau
     • Try/catch global
     • Message générique en cas d'erreur inconnue
  
  4️⃣ NOTIFICATIONS UTILISATEUR (TOAST)
  ─────────────────────────────────────
  
  ✅ Toast informatifs à chaque étape
     • 🔵 "Initialisation du dossier en cours... (Étape 1/2)"

     • 🔵 "Validation du dossier en cours... (Étape 2/2)"
     • 🎉 "Dossier AVA créé et validé avec succès !" (5 secondes)
  
  ✅ Toast d'erreur détaillés
     • Titre de l'erreur
     • Description avec message du serveur
  
  5️⃣ LOGS CONSOLE DÉTAILLÉS

     • ✅ [ÉTAPE 2/2] Validation réussie: {...}

  FRONTEND → BACKEND → FRONTEND
  ──────────────────────────────
  
  1. Utilisateur remplit le formulaire
     ↓
  2. Clic "Soumettre le dossier"
     ↓
  3. Validation côté client (champs obligatoires, formats, règles métier)
     ↓
  4. Préparation du DTO (nettoyage des champs temporaires)
     ↓
  5. ÉTAPE 1 : POST /api/operations-deleguees-mvt/initialisation
     ↓
  6. Réception : { refOperation: 123456, numDossier: 98765 }
     ↓
  7. ÉTAPE 2 : POST /api/operations-deleguees/validation/98765
     ↓
  8. Réception : OuvertureDossierDTO complet
     ↓
  9. Affichage succès + réinitialisation formulaire

  • Montants calculés et validés

  ⚠️ Nettoyage des données avant envoi
  ─────────────────────────────────────
  
  • Suppression des champs id temporaires (ajoutés côté frontend)
  • Suppression du champ fichier (non sérialisable en JSON)
  • Conservation uniquement des métadonnées (nom, extension)
  
  const cleanBeneficiaires = beneficiaires.map(({ id, ...rest }) => rest);
  const cleanDocuments = documents.map(({ id, fichier, ...rest }) => rest);
  const cleanMarches = avaMarcheMvtListe.map(({ id, ...rest }) => rest);
  
  ⚠️ Validation du numDossier
  ───────────────────────────
  
  • Vérification que numDossier est bien retourné par l'ÉTAPE 1
  • Arrêt du processus si numDossier manquant
  
  if (!creationResponse.numDossier) {
    toast.error('Erreur de réponse', {
      description: 'Le numéro de dossier n\'a pas été retourné'
    });
    return;
  }
  
  ⚠️ État isSubmitting
  ────────────────────
  
  • Désactive le bouton pendant toute la durée du processus
  • Empêche les doubles soumissions
  • Réactivé dans le bloc finally (toujours exécuté)
