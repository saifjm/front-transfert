│ 🎯 VUE D'ENSEMBLE                                                            │
└──────────────────────────────────────────────────────────────────────────────┘

  Le processus de soumission du formulaire d'ouverture AVA se déroule en
  DEUX ÉTAPES SÉQUENTIELLES avec deux appels API distincts :
  
  1️⃣ INITIALISATION → Création du mouvement (MVT)
  2️⃣ VALIDATION    → Transformation MVT → Opération déléguée finale
  
  ✅ Chaque étape valide et retourne des informations spécifiques
  ✅ Le processus s'arrête en cas d'erreur à n'importe quelle étape
  ✅ Des notifications toast guident l'utilisateur à chaque étape

┌──────────────────────────────────────────────────────────────────────────────┐
│ 🔐 GESTION DES ERREURS                                                       │
└──────────────────────────────────────────────────────────────────────────────┘

  Le système gère de manière robuste toutes les erreurs possibles :
  
  ✅ PARSING DES ERREURS API
  ──────────────────────────
  
  try {
    const errorData = await response.json();
    errorDetails = errorData.message || errorData.error || JSON.stringify(errorData);
  } catch (e) {
    errorDetails = `Code HTTP ${response.status} : ${response.statusText}`;
  }
  
  ✅ ARRÊT DU PROCESSUS EN CAS D'ERREUR
  ──────────────────────────────────────
  
  • Si ÉTAPE 1 échoue → ARRÊT (pas d'appel ÉTAPE 2)
  • Si ÉTAPE 2 échoue → ARRÊT (formulaire non réinitialisé)
  • Utilisateur informé précisément de l'erreur
  
  ✅ MESSAGES CONTEXTUELS
  ───────────────────────
  
  • 400 → "Requête invalide ou contrôle métier échoué"
  • 404 → "Numéro de dossier introuvable" + détails
  • 422 → "Contrôles métier non satisfaits" + contexte
  • 500 → "Erreur serveur lors de l'initialisation"
  
  ✅ GESTION DES EXCEPTIONS RÉSEAU
  ────────────────────────────────
  
  try {
    // Appels API
  } catch (error) {
    toast.error('Erreur lors de l\'enregistrement', {
      description: 'Veuillez réessayer ou contacter le support.',
    });
    console.error('❌ Erreur:', error);
  } finally {
    setIsSubmitting(false);
  }

│ 🧪 TESTS À EFFECTUER                                                         │
└──────────────────────────────────────────────────────────────────────────────┘

  TEST 1 : SUCCÈS COMPLET
  ───────────────────────
  
  1. Remplir formulaire complet valide
  2. Cliquer "Soumettre le dossier"
  3. Vérifier : Toast "Initialisation en cours..."
  4. Vérifier : Toast "Initialisation réussie" avec refOperation et numDossier
  5. Vérifier : Toast "Validation en cours..."
  6. Vérifier : Toast succès final "🎉 Dossier AVA créé et validé !"
  7. Vérifier : Formulaire réinitialisé
  8. Vérifier : Logs console détaillés
  
  TEST 2 : ERREUR ÉTAPE 1 (400)
  ─────────────────────────────
  
  1. Backend retourne 400 lors de l'initialisation
  2. Vérifier : Toast "Requête invalide ou contrôle métier échoué"
  3. Vérifier : Message d'erreur détaillé du serveur
  4. Vérifier : Pas d'appel ÉTAPE 2
  5. Vérifier : Formulaire conservé (données non perdues)
  6. Vérifier : Bouton redevient actif
  
  TEST 3 : ERREUR ÉTAPE 2 (404)
  ─────────────────────────────
  
  1. ÉTAPE 1 réussit
  2. Backend retourne 404 lors de la validation
  3. Vérifier : Toast "Numéro de dossier introuvable"
  4. Vérifier : Message "Le dossier XXXXX n'a pas été trouvé"
  5. Vérifier : Formulaire conservé
  
  TEST 4 : ERREUR ÉTAPE 2 (422)
  ─────────────────────────────
  
  1. ÉTAPE 1 réussit
  2. Backend retourne 422 (contrôles métier)
  3. Vérifier : Toast "Contrôles métier non satisfaits"
  4. Vérifier : Message détaillant le problème (RIB, matricule, etc.)
  5. Vérifier : Formulaire conservé
  
  TEST 5 : ERREUR RÉSEAU
  ──────────────────────
  
  1. Déconnecter le réseau
  2. Soumettre le formulaire
  3. Vérifier : Toast "Erreur lors de l'enregistrement"
  4. Vérifier : Message "Veuillez réessayer ou contacter le support"
  5. Vérifier : Logs console avec erreur réseau
